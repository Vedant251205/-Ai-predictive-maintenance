Technical documentation

System Architecture

A three-layer design: a Bootstrap front end, a Flask application layer, SQLite persistence and a Random Forest inference engine. The modular split keeps the platform maintainable and scalable.

Presentation layer

Front end

Server-rendered pages with progressive enhancement. No build step.

  • HTML5 semantic markup, skip links, ARIA labelling
  • Bootstrap 5 grid utilities over a custom dark SCADA theme
  • Chart.js 4 for every visualisation, one shared theme module
  • Font Awesome 6 iconography
  • Jinja2 templates: one base shell, four partials, thirteen pages
  • Live clock, collapsible sidebar, persistent backdrop
  • Reduced-motion and print stylesheets

Application layer

Flask 3.1 factory

Blueprints keep routing thin; services hold the logic.

  • app.py application factory, CSRF guard, error handlers
  • config.py single source for brand, thresholds, fleet and paths
  • routes/ auth, main, predict, history, api
  • services/ database, ml, prediction, fleet, alert, kiln, chatbot
  • utils/ validators, formatters, recommendations
  • Eight JSON endpoints under /api
  • Role-based sessions, PBKDF2 password hashing, audit trail

Intelligence layer

{{ card.algorithm }}

{{ card.n_estimators }} trees, max depth {{ card.max_depth }}, inside a {{ card.preprocessor }}.

  • Five numeric sensor channels plus machine class
  • StandardScaler on numerics, OneHotEncoder on the class
  • Binary target: will this asset fail
  • Health score = 100 - failure probability
  • RUL from a documented multi-factor degradation heuristic
  • Persisted with joblib, metadata published as JSON
